# Speed Go — نسخة اختبار وتكملة ربط (راكب/سائق + أدوات الإدارة)

## ملفات الحزمة
- `index.html`: تطبيق PWA موحّد للراكب والسائق.
- `admin-tools.html`: أدوات إدارة منفصلة لإصدار رموز الشحن وإسناد الرحلات.
- `shared/config.js`: رابط Supabase والمفتاح العام فقط؛ لا يحتوي service_role.
- `shared/api.js`: المصادقة والرحلات والمحفظة والـ RPCs.
- `supabase/migrations/20261023_speedgo_lifecycle_wallet_admin.sql`: توثيق لجزء من تغييرات قاعدة البيانات المطبقة على المشروع المتصل.
- `supabase/admin_bootstrap.sql`: إضافة أول مسؤول بعد إنشاء حسابه (استبدل البريد الوهمي قبل التنفيذ).
- `TEST_CHECKLIST_AR.md`: نتائج الفحوصات الآلية وقائمة الاختبارات اليدوية.
- `sw.js`, `manifest.json`, `icon.svg`: ملفات PWA.

## الربط الحالي
- المشروع المرتبط: `xvtbfncfkdzsxfuwrdmr` (Speed Go).
- قاعدة البيانات الحقيقية تحتوي جداول `profiles`, `driver_profiles`, `trips`, `driver_wallets`, `wallet_topup_codes`, `wallet_transactions`, `notifications`, `trip_events`, `admin_users` وغيرها.
- نُشرت وظيفة Edge Function باسم `redeem-wallet-code`، وأضيفت RPCs لشحن رمز مرة واحدة، وإصدار رمز، وتفعيل حالة السائق، وقبول الرحلة، وتحديث حالتها، وإسنادها من الإدارة.
- جدول `trips` و`notifications` ضمن Supabase Realtime في المشروع.
- أزيلت صلاحيات التعديل المباشر الحساسة عن الرحلات وملف السائق، وتُجرى تغييرات الحالة عبر RPCs محددة.

## إعداد أول مسؤول
وقت الفحص كانت جداول Auth والمستخدمين والمسؤولين والرحلات خالية (صفر حسابات). أنشئ حسابًا ببريدك من التطبيق، ثم افتح Supabase SQL Editor وشغّل `supabase/admin_bootstrap.sql` بعد استبدال البريد الوهمي ببريد حسابك. بعد ذلك افتح `admin-tools.html` وسجّل الدخول. لا تنفّذ هذا السكربت ببريد غير موثوق.

## طريقة الاختبار
1. استضف المجلد كاملاً على HTTPS؛ لا تفتح `index.html` عبر `file://` ولا ترفع `index.html` وحده.
2. افتح `index.html`، اختر راكباً أو سائقاً، وأنشئ حساباً باستخدام مزود Auth المفعّل في Supabase.
3. إذا كان تأكيد البريد/الهاتف مفعّلاً، أكمل التحقق أولاً ثم سجل الدخول.
4. حساب السائق الجديد ينتظر الموافقة. يجب أن توافق الإدارة على السائق في جدول `driver_profiles` قبل استقبال الرحلات.
5. افتح `admin-tools.html` بحساب موجود بالفعل في `admin_users`. يمكن إصدار رمز شحن وعرضه مرة واحدة، كما يمكن إسناد رحلة مفتوحة إلى سائق معتمد.
6. جرّب دورة الرحلة: طلب من الراكب → قبول من السائق المتصل المعتمد → السائق في الطريق → بدء الرحلة → إنهاء الرحلة. الإلغاء متاح قبل بدء الرحلة.

## نتائج الاختبارات المنفذة
- نجاح تطبيق تغييرات قاعدة البيانات على مشروع Supabase المتصل.
- تحقق من وجود الوظائف الست وصلاحية تنفيذها للمستخدمين المصادق عليهم؛ صلاحيات الإدارة والسائق تُفحص داخل الوظائف.
- تحقق من أن `trips`, `notifications`, `driver_profiles`, `call_signals` ضمن Realtime publication.
- فحص صياغة JavaScript باستخدام `node --check` وفحص سلامة ZIP بعد التجميع.

## اختبارات لم يمكن تنفيذها من هذه البيئة
- لم يُجرَ تسجيل دخول بحساب بشري حقيقي على هاتف؛ لا توجد بيانات اختبار/جلسة مستخدم متاحة، ولا يمكن محاكاة جهازك من هنا. يلزم اختبار مستخدم فعلي بعد استضافة HTTPS وتفعيل Auth.
- لم يُختبر SMS أو تأكيد البريد لأن ذلك يعتمد على إعداد مزود Auth.
- لا تدّعي هذه الحزمة جاهزية مكالمات WebRTC للصوت في الخلفية: يلزم استكمال واجهة الاتصال، وإعداد STUN/TURN، واختبار أذونات الميكروفون، أما الرنين الموثوق عند إغلاق التطبيق فيحتاج تكامل Push/native خاصاً بالنظام.
- الإشعارات اللحظية تعمل عند بقاء التطبيق نشطاً/متصلاً؛ إشعارات النظام الموثوقة عند الإغلاق تحتاج إعداد Push.
- لم يتم بناء APK في هذه الحزمة. لتحويل PWA إلى APK استخدم منشئ WebView يقبل ملفات الويب؛ بناء Android أصلي يحتاج Android SDK وتوقيعاً.

## أمان
لا تضع `service_role`, secret keys أو كلمة مرور قاعدة البيانات داخل ملفات العميل أو في مواقع تحويل عامة. مفتاح publishable/anon فقط مخصص للعميل. احتفظ بأكواد الشحن خارج المحادثات العامة.

## بناء APK عبر GitHub Actions
راجع `BUILD_ANDROID_AR.md`. يحتوي المشروع على workflow في `.github/workflows/build-android.yml`؛ من تبويب Actions شغّل `Build Speed Go Android APK` ثم نزّل Artifact. البناء Debug للتجربة فقط، ولم يتم تأكيد نجاح بناء Android في بيئة إنشاء هذه الحزمة بسبب تعذر إكمال تنزيل اعتماديات npm هنا.


- قسم **حسابات تجريبية** في لوحة التحكم: إنشاء راكب/سائق/متجر مع الهاتف أو البريد وكلمة المرور والاسم والصورة؛ يتطلب نشر دالة `admin-create-account` وتطبيق migration رقم 007.
